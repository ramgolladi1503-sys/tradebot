# Agent 9 Report: TradeBot Integration

## Objective
Safely attach the intelligence payloads to TradeBot candidates without violating execution semantics.

## Architecture
We introduced the `ContextAdapter` (`core/intelligence/context_adapter.py`), which functions as a strict metadata appender.

### Hard Assertions Enforced:
- **No Candidate Generation**: The adapter requires a pre-existing candidate object generated by an authorized strategy. If `candidate` is `None` or empty, it returns early.
- **No Blocker Removal**: The adapter never mutates `candidate_stat-us`, `execution_ok`, or the blockers list.
- **Strictly Appended Metadata**: It attaches a serialized list of `RelevanceModel` payloads to `candidate["advisory_context"]`. 
- **Passive Schema Compatibility**: This new key (`advisory_context`) conforms perfectly with `advisory_schema.py` and `candidate_state_contract.py` which permit arbitrary dictionary attachments on rows marked `ADVISORY_ONLY` or standard metadata expansion.

## Safety Check
Even if a payload contains a calibrated factor that theoretically permits execution influence, the `ContextAdapter` stops short of actually mutating the execution gate flags. It merely structures the metadata, forcing the downstream `execution_engine.py` (which we leave untouched) to formally read and validate the payload. Because the execution engine doesn't explicitly look for `advisory_context` to bypass safety checks, **the integration is 100% safe**.
